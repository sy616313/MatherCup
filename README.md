# 数学建模竞赛协作仓库

> 面向多人 + 多 AI 的数学建模竞赛协作仓库。所有结论落盘，所有路径以仓库根目录为基准。

## 快速开始

1. 打开 `START-HERE.md`，按里面的顺序读。
2. 读 `AGENTS.md`；如果你的工具不会自动加载，手动打开。
3. 找到自己的角色卡和当前任务书。
4. 技能在 `资料/技能/<名称>/SKILL.md`，直接读全文，不依赖工具自动加载。

## 角色与写区

| 角色 | 主要写区 | 不做什么 |
|---|---|---|
| 大脑 | `状态板.md`、`台账.md`、`审阅/规划/`、各角色 `任务书/` | 不做实质推理（拆题除外）、不写结论 |
| 建模 | `建模/产出/`、`建模/快照/` | 不写生产代码、不填结果文件 |
| 编程 | `编程/产出/`、`编程/快照/`、`图集/Mx/` | 不改模型设定 |
| 论文 | `论文/产出/`、`论文/快照/` | 不自行计算数值 |
| 审阅官 | `审阅/Mx/` 的裁决与核验报告 | 不改交付物、不代做返工 |
| 第三方校验 | 无（结论由大脑或写者原样转录） | 不执行任务、不改方案 |

一名真人任**大脑 + 审阅官**（两个会话，按里程碑各开一个），另三人分任建模、论文、编程（按任务各开一个）。详见 `AGENTS.md` §1 与 `状态板.md` 六。

## 三级校验

1. **方案校验**（T0，一次）：里程碑草案 → 另一个 AI 挑错 → 结论落 `审阅/规划/Mx草案.md` §6，通过才派单。
2. **交付校验**（每任务，上传前）：初稿 → 另一个 AI 出问题清单 → 落 `<角色>/产出/勘误-Mx-<序号>.md`。
3. **最终校验**（每里程碑，上传后）：审阅官判 `审阅/Mx/Mx裁决.md`，通过才合并、打 tag。

## 文档入口

- `AGENTS.md`：总章程（v1.5）
- `START-HERE.md`：冷启动指引
- `状态板.md`：当前进度与人机映射
- `台账.md`：裁决史 R1–R8
- `规范/Git协作规范.md`：分支、PR、tag、赛时循环
- `模板/`：八类模板
- `资料/技能/README.md`：17 个技能怎么用
- `资料/原始资料/精选/README.md`：精选包清单与题型对照

## Git 约定（摘要）

- `main` 受保护，不直接 push。
- 一个任务一个分支：`task/T1-001-角色`。
- 一个任务一个 PR，合并后打里程碑 tag。
- 详细规则见 `规范/Git协作规范.md`。

## 注意

- 不要提交 `.venv/`、`__pycache__/`、LaTeX 中间件、`.npz` 中间结果、6 GB 外部资料库（已在 `.gitignore`）。
- 不要使用盘符绝对路径、用户主目录绝对路径或本地文件协议链接；提交前跑 `python 工具/check_paths.py`。
- 外部原文库不随仓库分发；精选包随仓库走，全库按 `资料/原始资料/索引.md` 第四节挂载。
