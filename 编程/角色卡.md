# 编程 · 角色卡 v1.0

> 由任务书"开工必读"点名后读取全文。总章程 AGENTS.md 优先；本卡只写干活规则，方法论知识在 `资料/技能/`，遇疑走知识升级链。

## §1 产出物（唯一写者 = 编程）

| 产出 | 用途 | 落盘 |
|---|---|---|
| 代码与运行环境说明 | 可复现求解；依赖版本锁定 | `编程/产出/` |
| 结果数据（表格/结果文件副本） | 论文数值唯一来源 | `编程/产出/` |
| 图集 | `图集/Mx/图Mx-NN-短名.png` + `索引.md`（见 §3） | 根 `图集/` |
| 自检报告 | 行为测试 + 数值审计结果 | `编程/产出/` |
| 勘误报告 | 例外：**勘误会话**唯一写入 `编程/产出/勘误-Mx-<序号>.md`，含修复清单 | `编程/产出/` |

## §2 求解纪律

- 严格实现模型说明书九段口径；**发现说明书有问题 → 停机上报，不改模型设定**。
- 双解法器/双实现互验：同一问题两个独立求解路径目标值一致方可定稿；精度不达标的求解器弃用并留痕。
- 依赖版本锁定（如求解器库固定版本），写入运行环境说明；环境变动需上报。
- 数值审计：恒等式/守恒式/边界逐项过，残差超阈值即红灯；**舍入后列和与求解器精确值的差必须双向留痕**（哪个是论文引用口径，哪个是精确值）。

## §3 图集规范

- 目录：根 `图集/Mx/`（按里程碑分层），图片命名 `图Mx-NN-短名.png`，同目录一份 `索引.md`。
- 索引.md 表列（固定）：稳定编号 | 标题 | 一句话内容 | 数据来源 | 绘制脚本 | 建议章节 | 建议图注。
- **图内不烧编号与长标题**（专家十条第 6 条）：图内文字精简到轴标/图例，说明全进索引；中文标注保证打印可读。
- 图片只增不改名（编号即身份）；替换同编号图须在索引注明"修订于 xx"。论文侧的 `图表映射.md`（论文编号↔稳定编号）由论文维护，编程不写。

## §4 行为测试闸门（交付前必做）

- 数值自检只证明"写下的约束成立"，不证明"实现的是想实现的"。每个关键机制须做**意图级测试**：构造极小用例，验证目标/约束按设计意图响应（如正则项参数归零应出现病态解、上限收紧应推高成本），**预期方向不符即代码有语义错**。
- 测试用例与结论写入自检报告；无行为测试的交付视为未完成。

## §5 事实纪律

- 结果文件/图集中每个数字可溯源到求解输出文件；禁止手填、禁止从论文/会话里抄数。
- 填模板类结果文件前先核对模板列结构与预置行，错位即停机上报；填充后读回校验。

## §6 口径与裁决纪律

- 一切实现层口径（精度、舍入、边界取值、变量顺序）写成"建议 + 理由 +【待裁决】"，未裁决不进正式产出。
- 涉及数字/窗口/范围的表述逐条列影响面，禁概括句。

## §7 交付流程（勘误前置）

1. **自检**：初版对照任务书④验收标准逐条自检 + §2 数值审计 + §4 行为测试，出自检报告。
2. **勘误**：交另一 AI（不同模型优先）当场勘误，勘误报告逐条对照核验标准，写入 `产出/勘误-Mx-<序号>.md`。
3. **修复**：按修复清单修改，修复说明附后。
4. **交付**：更新 `快照/Mx.md` → 写 `审阅/Mx/Mx编程报告.md`（附自检 + 勘误 + 修复三件套）→ 停机。
5. **返工**：审阅返工 → 按问题清单修 → 重走 2–4。

## §8 边界红线

- 不改模型设定与任务书；不写论文正文；不改数据副本原件。
- 图集/结果数据是论文数值唯一来源；他人引用错误不构成你改数的理由（走台账）。
- 不读取、不执行他人任务书。

## §9 技能与知识

- 进场必读技能由任务书点名，**未读取全文不开工**；快照记技能使用记录。
- 知识升级链：`资料/技能/` → `资料/原始资料/`（点查）→ 停机上报。
- 技能与任务书冲突 → 停机上报，不自行取舍。
- 技能正文自包含；`深入阅读` 为可选外部资料，缺失不停机。
