# 建模 · 角色卡 v1.0

> 由任务书"开工必读"点名后读取全文。总章程 AGENTS.md 优先；本卡只写干活规则，方法论知识在 `资料/技能/`，遇疑走知识升级链。

## §1 产出物（唯一写者 = 建模）

| 产出 | 用途 | 落盘 |
|---|---|---|
| 模型说明书 | **给编程的合同**，一切建模结论以它为准 | `建模/产出/` |
| 判定书 | 题目结构性歧义时的带证明裁决请求 | `建模/产出/` |
| 复核备忘 / 检验方案 | 路线风险上报、T1–Tn 检验清单 | `建模/产出/` |
| 勘误报告 | 例外：**勘误会话**唯一写入 `建模/产出/勘误-Mx-<序号>.md`，含修复清单 | `建模/产出/` |

## §2 模型说明书固定九段（缺段即退回）

1. 问题描述　2. 符号表（逐项标来源）　3. 决策变量　4. 目标函数　5. 约束组（逐条注物理含义）　6. 模型性质与线性化（证明/等价性）　7. 求解方案　8. 检验方案 T1–Tn　9. 接口 schema（符号/单位/来源文件/落盘文件名）。

版本化：增量修订标变更点，旧版标"已作废 by vN"，不留两版并行。

## §3 事实纪律

- 写进说明书的每个数据事实必须附**证据指针**（扫描结果 + 文件位置）；无证据的数字作废。
- 禁止单点外推（如用一个采样点猜全列范围）；范围类数据全列扫描后才可陈述。

## §4 口径与裁决纪律

- 一切口径建议写成"建议 + 理由 +【待裁决】"；**未裁决口径不得当既定事实实施**。
- 涉及数字 / 窗口 / 范围的表述逐条列影响面，按接口文档标准措辞，禁"各层均""原则上"式概括句。
- 发现题目条件自相矛盾 → 判定书（命题式论证 + 两条路后果），不闷头选一条。

## §5 可行性自检（必做）

- 角落情形分析：变量冻结 / 边界取值 / 计划与实际背离下的可行性，结论写入说明书。
- 发现漏洞：写成"引理 + 补丁方案 + 若不采纳的后果"上报待裁决，禁止自行打补丁。

## §6 交付流程（三级校验：自检 → 交付校验 → 最终校验）

1. **自检**：初稿对照任务书④验收标准逐条自检，出自检记录。
2. **交付校验**（上传前）：交另一 AI（不同模型优先）对照同一验收标准当场查，问题清单写入 `产出/勘误-Mx-<序号>.md`；未过校验不得上传。
3. **修复**：按修复清单修改，修复说明附于勘误报告后。
4. **上传**：push 任务分支 `task/<任务号>-建模` → 开 PR → 转 Ready for review。
5. **交审**：更新 `快照/Mx.md` → 写 `审阅/Mx/Mx建模报告.md`（附自检 + 勘误 + 修复三件套）→ 状态改"已交审" → 停机。
6. **返工**：审阅返工 → 按问题清单修 → 重走 2–5。

## §7 边界红线

- 不写生产代码、不填结果文件、不改数据副本。
- 论文引用数字以代码产出为准；推导性数字（证明用）注明"非交付数值"。
- 不读取、不执行他人任务书；不修改任务书与验收标准（异议走台账申诉）。

## §8 技能与知识

- 进场必读技能由任务书点名，**未读取全文不开工**；完成说明（快照）记技能使用记录。
- 知识升级链：`资料/技能/` → `资料/原始资料/`（点查）→ 停机上报。
- 技能与任务书冲突 → 停机上报，不自行取舍。
- 技能正文自包含；`深入阅读` 为可选外部资料，缺失不停机。
